## 1. 为什么单独写这份说明

会上董事长以"刑法证据派"的视角追问：服务商**理论上**能不能看到客户数据？当场我方以"99.999% 可控"收尾，但没有把"技术可能性"和"法律 / 合同约束"拆开讲清楚。本说明按三层回答：

1. **技术层**：我方技术上能接触到什么、不能接触到什么；
2. **合同层**：双方签什么、违约怎么罚；
3. **法律层**：适用哪些法律、各方承担什么角色与责任。

结论先行：**我们不回避"技术上存在可能"，而是通过技术限制 + 合同约束 + 法律责任 + 可审计，让"可能"不可行、不划算、且一定会被发现。**

## 2. 技术边界：我方能 / 不能访问什么

### 2.1 我方技术上可以接触的

| 对象 | 用途 | 限制 |
|-|-|-|
| 系统运行指标（CPU、内存、存储用量、报错码） | 保障可用性、容量规划 | 不含业务内容 |
| 账号与计费元数据（AI 员工数量、调用量） | 计费、对账 | 不含任务内容 |
| 经 X 集团临时授权开放的特定数据 | 排障、定制开发调试 | 限定范围与时长，全程审计，到期自动回收 |

### 2.2 我方默认不能接触的

| 对象 | 如何保证 |
|-|-|
| AI 员工产出的报告、看板、合同审查结果 | 存于 X 集团独占云电脑，我方运维账号默认无读取权限 |
| 企业知识库内容 | 分区存储、静态加密；密钥托管方案部署前与风控负责人确认 |
| 万得、通达 OA 等连接器账号凭证 | 由 X 集团提供并可随时吊销，我方不留存明文 |
| 员工与 AI 员工的会话记录 | 仅 X 集团授权角色可见 |

### 2.3 坦白讲的"理论可能"

与云服务行业普遍情况一样，掌握底层基础设施的一方（云厂商、我方运维）在**理论上**具备绕过应用层权限的能力。我方的控制方式是：

- 把高权限账号数量压到最少，并实行双人复核；
- 所有高权限操作写入只追加的审计日志，X 集团可独立导出核查；
- 在合同中把"未经授权访问"定义为重大违约（见第 3 节）。

## 3. 合同边界

| 条款 | 核心内容（拟定） |
|-|-|
| 数据所有权 | X 集团数据及 AI 员工产出全部归 X 集团所有 |
| 使用目的限制 | 我方仅为履行本合同处理数据，不得用于模型训练、对外提供或其他用途 |
| 保密义务 | 覆盖我方全体员工及分包方，合同终止后持续有效 |
| 访问授权 | 我方访问业务数据须经 X 集团书面 / 系统内临时授权 |
| 分包管理 | 云资源与第三方审计机构等分包方需事先告知，并承担同等保密义务 |
| 跨境限制 | 海外模型通道默认关闭，启用需 X 集团书面授权并满足数据出境相关规定 |
| 审计权 | X 集团有权自行或委托第三方对我方履约情况进行审计 |
| 违约责任 | 未经授权访问或泄露视为重大违约，承担赔偿责任并支持 X 集团解除合同（赔偿口径待法务确定） |
| 合同终止 | 我方配合全量导出，并在约定期限内删除、出具删除确认 |

## 4. 法律边界与数据处理角色

### 4.1 适用法律框架

- 《网络安全法》：网络运营安全、安全事件报告等基础义务；
- 《数据安全法》：数据分类分级、重要数据保护、数据出境管理；
- 《个人信息保护法》：个人信息处理规则、委托处理、跨境提供等要求；
- 金融、能源等行业监管规定：如 X 集团所在板块有专门要求，以行业规定为准（待法务按板块补充）。

### 4.2 各方角色

| 主体 | 角色 | 主要责任 |
|-|-|-|
| X 集团 | 数据处理者 / 个人信息处理者（决定处理目的与方式） | 确定数据范围、授权使用、员工与被投企业数据的合法来源 |
| 我方 | 受托处理方（按 X 集团指示处理） | 按约定目的和方式处理、采取安全措施、协助 X 集团履行合规义务、不得超范围处理 |
| 云资源提供方 | 我方分包方 | 基础设施安全，承担与我方同等的保密约束 |
| 模型服务方 | 按调用处理的服务提供方 | 以服务条款约束不留存、不训练（具体以各方条款为准，待法务逐一核对） |

### 4.3 "能看 vs 不能看"的法律含义

董事长会上的类比——"理论上能 / 法律上不能"——在本项目中具体体现为：我方作为受托处理方，**超出委托范围访问或使用客户数据，既构成合同违约，也可能违反上述法律中关于委托处理和数据安全的规定，情节严重的还可能涉及刑事责任**。这正是"能做到但不会做"的约束来源，而不只是商业信誉。

## 5. 审计与安全事件处理

### 5.1 审计机制

| 方式 | 频次 | 执行方 |
|-|-|-|
| 审计日志自助导出 | 随时 | X 集团管理员 |
| 我方高权限操作月报 | 每月（示意） | 我方提交，风控负责人审阅 |
| 年度合规审计 | 每年（示意） | X 集团自行或委托第三方 |
| 第三方安全测评 / 认证材料 | 合规专题 Demo 时提供现有材料；后续取得的认证在获得后同步 | 我方提供 |

### 5.2 安全事件响应流程（示意时限）

| 步骤 | 动作 | 时限 |
|-|-|-|
| 1. 发现 | 监控告警或人工报告 | — |
| 2. 通知 | 告知 X 集团对接人与风控负责人 | 确认后尽快，不超过 24 小时（示意） |
| 3. 遏制 | 隔离受影响云电脑、吊销相关凭证 | 立即 |
| 4. 调查 | 基于审计日志还原过程，形成事件报告 | 3–5 个工作日（示意） |
| 5. 报告 | 协助 X 集团按法律要求向主管部门报告、通知受影响主体 | 依法定要求 |
| 6. 复盘 | 整改措施与验证结果书面提交 | 事件关闭前 |

## 6. 可控性说明表

| 风险场景 | 技术控制 | 合同控制 | 法律约束 | 可发现性 |
|-|-|-|-|-|
| 我方员工私自查看客户数据 | 默认无权限 + 双人复核 | 重大违约 + 赔偿 | 违反委托处理与数据安全义务 | 审计日志可查 |
| 云资源方工程师访问 | 专属资源 + 静态加密 | 分包方同等保密义务 | 同上 | 云侧日志 + 我方日志 |
| 插件窃取数据 | 双重审计 + 沙箱 + 最小权限 | 第三方插件责任条款 | — | 越权调用告警 |
| 外链误传 | 默认关闭 + 有效期 + 水印 | 内部使用规范 | — | 访问留痕、可撤回 |
| 数据经海外通道出境 | 默认关闭 + 数据分级 + 脱敏 | 书面授权前不得启用 | 数据出境相关规定 | 海外调用单独筛查 |
| 合作终止后数据残留 | 全量导出 + 删除 | 删除确认书 | 个人信息删除义务 | 删除确认 + 抽查 |

> "99.999% 可控"的含义：剩余风险来自底层基础设施的理论可能性，通过上表四个维度叠加，使任何越权行为都**留痕、可追责、代价远大于收益**。
