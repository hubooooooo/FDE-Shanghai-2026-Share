# 内部内容平台·内容（课程）体系与入库协作说明

> 本文为模拟重建的示例文档：原件为项目内部资料、未随资料包公开，此处根据资料包其他文档的上下文重建，结构与方法可参考，具体数字与细节为示意。

| 项目 | 内容 |
|-|-|
| 文档性质 | 入库与发布的主要规范 |
| 维护人 | CMS 总负责人；平台规则与技术负责人共同确认 |
| 适用范围 | 英语短剧课程从“审核通过的生产成果”进入核心 CMS，到组装为可发布课程的全过程 |
| 上游依据 | 《内容生产流程会议总结》决策二（入库边界）、决策三（双维度审核） |

## 一、基本原则

1. **只存最终可消费内容。**核心 CMS 只接收最终会被用户看到或使用的内容。专家标注稿、审校汇总报告、实习生修改记录、Agent 中间产物留在生产工具中。
2. **先原子、后组合。**剧本、视频、字幕、知识点、题目、视觉资产等原子内容先入库，剧集、短剧、课程只引用原子内容的稳定 ID，不复制内容。
3. **稳定 ID 不随修改变化。**内容修改产生新版本号，ID 保持不变；只有“语义上是另一个东西”时才新建 ID。
4. **上传不等于可用。**所有内容入库后一律进入草稿／待审核状态，经检查与审核后才能被发布版本引用。
5. **谁生产谁上传，谁负责谁签字。**编导上传剧集内容，教研上传知识点与题目，设计上传视觉资产，出题与组装负责人负责组装与整体确认。

## 二、内容实体

| 实体 | 定义 | 上传／维护人 | 关键字段 |
|-|-|-|-|
| 学习主线 | 按语言与等级组织的学习路径，课程挂在主线下。 | CMS 总负责人 | 语言、等级、学习方式、排序 |
| 课程 | 面向用户的一门完整课，由一部短剧 + 文本练习题库 + 分发规则组成。 | 出题与组装负责人 | 学习主线、等级、短剧、版本号 |
| 短剧 | 有序剧集的集合，对应某一语言等级的完整故事。 | 编导负责人 | 等级、集数、封面、人物、角色 |
| 剧集 | 一集可播放的学习单元，绑定正片、字幕、知识点和片中题时间点。 | 编导负责人（教研负责关联知识点与片中题） | 集序、源剧本编号、时长 |
| 剧本 | 某一等级的正式英文剧本（含知识点标注）。 | 编导负责人 | 等级、语言、对白词数、审核状态 |
| 视频 | 剧情正片，以及片中题配套互动视频。 | 编导负责人 | 类型（正片／互动）、时长、分辨率、转码状态 |
| 字幕 | 与视频时间轴对齐的字幕文件。 | 编导负责人 | 语言、对应视频、时间轴格式 |
| 知识点 | 词汇、短语、语法、功能表达等最小教学单元。 | 教研负责人 | 知识点 ID、标准写法、CEFR 级别、状态 |
| 片中互动题 | 固定在剧集视频时间点上的互动题（知识点题或剧情理解题）。 | 教研负责人 | 剧集、时间点、顺序、互动视频、答案 |
| 文本练习题 | 独立题库中的练习题，不进入视频时间轴。 | 教研负责人 | 主知识点、题型、学习方式、答案、解析 |
| 人物 | 剧情中的人物设定（姓名、身份、关系），跨等级共享。 | 编导负责人 | 姓名、简介、所属短剧系列 |
| 角色 | 人物在 App 与视频中使用的形象资产（头像、立绘、声线说明）。 | 设计负责人 | 对应人物、版本、尺寸 |
| 封面 | 短剧和课程的展示封面。 | 设计负责人 | 尺寸规格、适用对象 |
| 图片 | 题目或页面所需的配图、场景图。 | 设计负责人 | 用途、对应题目／剧集 |

> 人物与角色的区别：Sophia 这个“人”是人物；她在 B2 英文版中的头像、立绘是角色。换画风只新增角色版本，不改人物。

## 三、依赖顺序

入库与组装必须按下列顺序进行，上层实体只能引用已存在的下层实体：

```text
第 1 层  知识点、人物、图片、封面
第 2 层  剧本、视频（正片／互动）、字幕、角色（依赖人物）
第 3 层  片中互动题（依赖知识点、互动视频）、文本练习题（依赖知识点、图片／音频）
第 4 层  剧集（依赖剧本、正片、字幕、知识点、片中互动题）
第 5 层  短剧（依赖剧集、封面、人物、角色）
第 6 层  课程（依赖学习主线、短剧、文本练习题库、分发规则）
第 7 层  课程发布版本（冻结课程及其引用的全部内容版本）
```

删除或下架下层内容前，系统必须展示被哪些上层实体引用；被已发布版本引用的内容不可删除，只能在新版本中替换。

## 四、稳定 ID 命名规则

格式：`{实体前缀}-{作品代号}-{等级}-{语言}[-{集序/编号}][-{序号}]`。作品代号使用英文驼峰，不使用中文与空格。

| 实体 | 前缀 | 示例 | 说明 |
|-|-|-|-|
| 学习主线 | Track | Track-EN-B2 | 语言 + 等级 |
| 课程 | Course | Course-SampleDrama-B2-EN | 稳定 ID 不含版本 |
| 课程发布版本 | — | **Course-SampleDrama-B2-EN-V1** | 稳定 ID + `-V{n}`，发布时生成 |
| 短剧 | Drama | Drama-SampleDrama-B2-EN | |
| 剧集 | Episode | Episode-SampleDrama-B2-EN-E02-1 | `E02-1` 对应源剧本编号“第二集 2-1” |
| 剧本 | Script | Script-SampleDrama-B2-EN-E02-1 | 一集一份正式剧本 |
| 正片视频 | Video | Video-SampleDrama-B2-EN-E02-1-MAIN | |
| 互动视频 | Video | Video-SampleDrama-B2-EN-E02-1-IQ01 | 与片中题序号对应 |
| 字幕 | Sub | Sub-SampleDrama-B2-EN-E02-1-EN | 末段为字幕语言 |
| 知识点 | KP | KP-B2-0123 | 系统生成，与 CMS 知识库一致（如 KP-B1-0001） |
| 片中互动题 | IQ | IQ-SampleDrama-B2-EN-E02-1-01 | 末段为本集内顺序 |
| 文本练习题 | TQ | TQ-B2-000456 | 系统生成，按知识点关联，不绑剧集 |
| 人物 | Char | Char-SampleDrama-Sophia | 跨等级共享，不带等级 |
| 角色 | Role | Role-SampleDrama-Sophia-B2 | |
| 封面 | Cover | Cover-SampleDrama-B2-EN | |
| 图片 | Img | Img-SampleDrama-E02-1-VeniceBnB | |

规则：

- ID 一经创建不可修改、不可复用；废弃 ID 保留映射记录。
- 内容修改只增加实体版本号（v1、v2…），不改 ID。
- 生产侧提交“稳定 ID 对照表”，列出每个实体的 ID、生产文件名、等级、版本、上传人，入库时逐行核对。

## 五、关联关系

| 关系 | 基数 | 约束 |
|-|-|-|
| 学习主线 — 课程 | 1 : N | 课程等级必须与主线等级一致 |
| 课程 — 短剧 | 1 : 1 | 一个课程版本只绑定一部短剧的一个版本 |
| 短剧 — 剧集 | 1 : N（≥ 1） | 集序连续、不重复 |
| 剧集 — 正片 / 字幕 | 1 : 1 / 1 : N | 字幕时间轴不得超出正片时长 |
| 剧集 — 知识点 | N : M（每集 ≥ 1） | 知识点等级与剧集等级一致，状态为“可用” |
| 剧集 — 片中互动题 | 1 : N（≥ 1） | 时间点在视频时长内，按时间顺序递增 |
| 知识点 — 文本练习题 | 1 : N（≥ 1） | 每个知识点至少 1 道已发布文本题 |
| 人物 — 角色 | 1 : N | 短剧引用的角色必须对应其人物 |

## 六、上传流程

1. **准备：**生产侧按稳定 ID 对照表整理文件和元数据（等级、语言、版本、关联 ID）。
2. **申请上传地址：**调用上传接口，按实体获取**短时有效的上传地址**（示意：15 分钟有效，过期重新申请）。
3. **上传文件：**直传媒体与文本文件，客户端不经过业务服务器中转。
4. **系统检查：**
   - 元数据检查：必填字段、枚举值、ID 格式、关联 ID 是否存在、等级是否一致。
   - 媒体检查：文件格式、时长、分辨率、音轨、字幕编码与时间轴是否可解析。
5. **转码：**视频转为播放所需的多码率格式，生成封面帧；转码失败的媒体不可被引用。
6. **进入草稿／待审核：**全部内容入库后状态为草稿或待审核，不会被任何发布版本使用。
7. **结果回执：**系统返回每个文件的检查结果、转码结果和失败原因，生产侧据此修正并重新上传。

> 例：上传第二集 2-1 时，正式英文剧本、正片、字幕、片中互动题包、文本题、Sophia／Jacob 角色和民宿场景图入库；专家审校过程稿不入核心库。

## 七、发布前检查清单

组装课程后，系统按依赖顺序自动检查以下各项。**任何一项失败，都退回对应负责人修改并重新检查**：

| 序号 | 检查项 | 失败时退回 |
|-|-|-|
| 1 | 学习主线和等级有效 | CMS 总负责人／出题与组装负责人 |
| 2 | 短剧至少有 1 集，且集序连续不重复 | 编导负责人 |
| 3 | 每集正片和字幕有效 | 编导负责人 |
| 4 | 每集至少有 1 个合法知识点 | 教研负责人 |
| 5 | 每集至少有 1 道已发布、时间合法且顺序递增的片中互动题 | 教研负责人（时间点涉及画面时同步编导） |
| 6 | 每个知识点至少有 1 道已发布的文本练习题 | 教研负责人 |
| 7 | 所有媒体可用，等级和知识点关系合法 | 对应媒体上传人／教研负责人 |

自动检查通过后，还需三方人工确认：编导负责人完成剧集内容维度签字，教研负责人完成知识点与题目维度签字，出题与组装负责人完成整体确认。三项齐全后，才可生成发布版本。
