## 一、为什么要拆成五个阶段

讨论起点是一个问题：“一门课到底是什么时候‘生成’的？”大家的理解不一致——编导认为视频剪完就是课，教研认为题目审完才算，技术认为发布版本生成才算。

为了让各方说同一种语言，本稿把一门课从无到有拆成五个阶段，每个阶段只回答一个问题：

```text
① 短剧内容   —— 讲什么故事？
      ↓
② 教学内容   —— 在故事里教什么、怎么练？
      ↓
③ 课程入库   —— 怎么变成平台上可编排、可审核、可发布的课程？
      ↓
④ 个性化     —— 给哪个用户、在什么时候、发哪些内容？
      ↓
⑤ 消费       —— 用户在 App 里怎么看、怎么答、怎么回流数据？
```

前三个阶段属于“生产侧”，结果是一个**冻结的课程发布版本**；后两个阶段属于“服务侧”，在发布版本之上按用户动态组合。生产侧不为单个用户定制内容。

## 二、阶段一：短剧内容

| 项目 | 说明 |
|-|-|
| 输入 | 中文原始剧本（只有 B1、B2、C1 三个级别）、人物设定、分集与场次 |
| 主要动作 | 中文剧本入库前审核 → 分级翻译与 Skills 审核 → 本土化专家改写基准级 → 生成其他等级 → 实习生统一优化 → 剧情视频与字幕制作 → 视频八项审核 |
| 输出 | 各等级正式英文剧本、审核通过的剧情视频与字幕、人物与角色视觉资产 |
| 负责人 | 编导负责人（第一负责人）、本土化专家／实习生、设计负责人 |

讨论要点：

- 剧情和人物关系在所有等级中必须一致，只改变语言难度。以《示例短剧》第二集 2-1 为例，各等级都要保留“钱包和护照被盗—Jacob 无法确认身份—拒绝入住—两人在狂欢节见过”的完整线索。
- 视频是按“正式剧本”制作的，因此剧本一旦进入视频制作就应冻结；后续语言微调若影响台词，必须同步字幕并重新审核视频。
- **待确认：**不同等级是否共用同一套剧情视频（只换配音和字幕），还是每个等级单独生成视频。目前倾向“画面共用、配音与字幕分等级”，但口型同步成本尚未评估。

## 三、阶段二：教学内容

| 项目 | 说明 |
|-|-|
| 输入 | 各等级正式剧本、对应等级知识库、已确认题型 |
| 主要动作 | 匹配候选知识点 → 确定单集与整剧数量 → 按固定题型生成候选题 → 系统检查与教研审核 → 制作片中互动题和配套互动视频 → 整理文本练习题库 |
| 输出 | 每集核心知识点、片中互动题包（含时间点和互动视频）、文本练习题库 |
| 负责人 | 教研负责人（第一负责人）；片中题位置与互动视频由编导配合 |

讨论要点：

- 教学内容分两条线：**片中互动题**固定在视频时间点上，属于“看剧时的体验”；**文本练习题**是独立题库，不进入视频时间轴，供剧后练习、每 5 集复习和跳集测试调用。
- 每集最终核心知识点约 90 个英文对白词对应 1 个，±1，每集最多 3 个。第二集 2-1 的候选为 report a theft、verify your identity、under Italian law 等。
- 片中题可以是知识点题，也可以是人物、事件、原因类的剧情理解题，例如“为什么 Jacob 不能让 Sophia 入住？”
- **待确认：**剧情理解题是否也需要关联知识点 ID。教研倾向关联“剧情理解”虚拟知识点以便统计，技术倾向单独标记题目类别。

## 四、阶段三：课程入库

| 项目 | 说明 |
|-|-|
| 输入 | 审核通过的剧本、视频、字幕、知识点、两类题目和视觉资产，以及稳定 ID 对照表 |
| 主要动作 | 上传原子内容 → 创建剧集 → 组成短剧 → 组装课程 → 系统自动检查 → 双维度人工签字 + 整体确认 → 生成发布版本 |
| 输出 | 不可直接修改的正式课程发布版本，例如 Course-SampleDrama-B2-EN-V1 |
| 负责人 | 出题与组装负责人（组装与整体确认）、CMS 总负责人（平台协调）、技术负责人（发布能力） |

讨论要点：

- 依赖顺序自下而上：原子内容 → 剧集 → 短剧 → 课程 → 发布版本。上层只引用下层的稳定 ID，不复制内容。
- 只有最终用户可消费的内容进入核心 CMS（见《内容生产流程会议总结》决策二）。
- 发布版本冻结后不可覆盖，改动走新版本；严重问题可召回。详见《CMS 发布与生命周期管理》。
- 该阶段的检查项已经转为正式规范，见《内容体系与入库协作说明》第六节。

## 五、阶段四：个性化

| 项目 | 说明 |
|-|-|
| 输入 | 已发布课程版本、用户等级与学习方式、学习进度、答题记录 |
| 主要动作 | 选择学习主线与等级 → 决定当集片中题实际出现哪些 → 组合剧后练习 → 安排每 5 集复习 → 跳集测试 |
| 输出 | 面向单个用户的学习序列与题目组合 |
| 负责人 | 技术负责人（服务端分发）；分发规则由出题与组装负责人定义 |

讨论要点：

- 片中题：生产侧固定“候选时间点”，服务端按视频时长控制上限，并保证实际被选中的题目间隔 > 45 秒。（早期会议“最多 2 题、间隔 30 秒”已不再使用。）
- 剧后练习：从文本练习题库中按本集知识点抽题，优先未练过、近期答错的知识点。
- 学习方式：全英文学习与母语辅助学习使用不同的已确认题型。
- **待确认：**用户等级测试结果与课程等级的映射是否允许“跨一级”推荐（例如 B1 用户试听 B2 课程）。
- **待确认：**每 5 集复习的抽题比例（本 5 集知识点 vs 更早知识点）。当前草案为 7:3，尚无数据支撑。
- **待确认：**跳集测试通过线。草案为正确率 ≥ 80%，需教研确认。

## 六、阶段五：消费

| 项目 | 说明 |
|-|-|
| 输入 | 个性化后的学习序列 |
| 主要动作 | 用户看剧 → 片中答题（进入题目—出题—等待—答对／答错讲解—返回剧情）→ 剧后练习 → 复习／测试 |
| 输出 | 学习记录、答题正确率、耗时、跳过率、反馈 |
| 负责人 | 技术负责人；数据回流给教研与编导 |

讨论要点：

- 答题数据回流 CMS 看板，用于发现高错题、低区分度题、长期未调用题，触发题目修订（走新版本，不覆盖线上版本）。
- 用户反馈的内容错误（如字幕错误）进入问题单，严重时触发召回。
- **待确认：**观看完成率、片中题跳过率是否回流给编导作为剧情节奏的评估指标，以及由谁定期复盘。
