## 上线流程

> **适用范围：**从中文剧本进入制作，到分级本土化剧本、知识点和两类题目、剧情与教学视频、课程编排入库，再到审核发布的完整流程。每一步都必须有明确输入、负责人、输出和回退位置。

### 参考文档与使用规则

> **使用原则：**当前正式规范与最新详细方案优先，其次是正式总结／产品需求文档，再其次是会议纪要；标有“待讨论”“待确认”的内容只作背景参考，不能直接作为验收标准。发生冲突时，以更晚、更具体、已确认的规范为准，并在项目中记录采用版本。

### 板块一｜剧本本土化改写

> **完成标准：**各等级剧本必须保留原剧情和人物关系，语言自然可演，目标等级正确，并经过对应人员审核。

#### Step 1｜接收中文剧本并完成入库前审核

| **输入** | 完整中文剧本、人物设定、分集和场次信息。 |
|-|-|
| **负责人** | 内容／编导团队提供；编导负责人审核中文内容。 |
| **操作** | 检查人物、剧情冲突、前后逻辑、对白、分集和场次是否完整；不通过时退回编导修改。 |
| **输出** | 审核通过、可进入翻译改写的中文源剧本。 |
| 注意点 | 中文剧本只有B1 B2 和C1三个级别 |
| **《示例短剧》例子** | 第二集 2-1：Sophia 在威尼斯民宿说明钱包和护照被盗；Jacob 因无法确认身份而拒绝她入住；最后揭示两人在狂欢节上见过。 |

#### Step 2｜分级翻译并由 Skills 审核

| **输入** | 审核通过的中文源剧本、目标语言、目标语言等级。 |
|-|-|
| **负责人** | 翻译 Skill、改写 Skill、审核 Skill 自动执行； |
| **操作** | 先生成目标等级英文稿，再检查剧情是否忠实、角色是否一致、语言等级和表达是否合格。审核不通过时返回本步骤重新翻译改写。 |
| **输出** | 通过 Skills 审核、等待专家处理的英文稿。 |
| **项目文档／规范** | 《B1/B2/C1 英语短剧剧本语言与知识点要求》；<br>Skill 地址：（内部 Skill 仓库） |
| **《示例短剧》例子** | 将“没有护照，我不能确认你的身份”改写为符合目标等级的自然英文，同时保留 Jacob 拒绝入住的剧情原因。 |

#### Step 3｜本土化专家审核并改写

| **输入** | Skills 审核通过的目标等级英文稿、中文／源级剧本、目标等级要求和知识库匹配结果。 |
|-|-|
| **负责人** | 本土化专家 |
| **操作** | 人工检查语言是否自然、语法是否正确、角色语气和台词是否可表演、文化表达是否安全、语言等级是否合适、知识点是否自然融入，同时保持剧情和人物关系不变。未通过时返回 Step 2 >  重新分级翻译。 |
| **输出** | ① 专家改写完成的基准级剧本；② 在飞书剧本中标出修改并写明原因；③ 审校汇总报告，包含整体评价、各类问题数量和修改建议；④ 专家审核状态。 |
| **项目文档／规范** | 《剧本人工审校需求及交付标准》；《剧本 Learning 审核标准》；《剧本语言与知识点要求》。 |
| **《示例短剧》例子** | 专家不仅确认 Sophia 的紧张和惊喜、Jacob 的冷淡与警惕能通过自然英文对白表现，还要在飞书稿中标出修改内容，并提交问题数量与修改建议汇总。 |

#### Step 4｜根据专家基准稿生成其他语言等级

| **输入** | 专家改写基准级剧本、需要生产的其他语言等级。 |
|-|-|
| **负责人** | CEFR 分级改写 Skill／Agent。 |
| **操作** | 以专家稿为唯一剧情基准，调整词汇、句长和语法复杂度，生成 A2、B1、B2、C1 等所需版本；剧情、人物关系和关键信息不能改变。 |
| **输出** | 其他语言等级的待优化剧本。 |
| **项目文档／规范** | 《各等级台词词汇占比和语言要求》；现行分级规则：从源等级向上或向下调整 1 级。 |
| **《示例短剧》例子** | 不同等级都保留“护照丢失—无法确认身份—拒绝入住—面具舞伴身份揭示”的完整剧情，只改变英文表达难度。 |

#### Step 5｜本土化实习生统一优化并确认正式剧本

| **输入** | 由专家基准稿生成的各等级剧本、专家标注稿、审校汇总报告和对应等级知识库。 |
|-|-|
| **负责人** | 本土化实习生；本土化专家负责抽查和重大问题复核。 |
| **操作** | 逐集检查拼写、语法、标点、称呼、角色语气、双语对应、知识点标注和语言等级；按《剧本 Learning 审核标准》完成整体检查。小问题直接修正，影响剧情、等级或本土化质量的问题返回专家或 Step 4。 |
| **输出** | A2、B1、B2、C1 等各等级完善版正式剧本、问题修改记录和最终审核状态。 |
| **项目文档／规范** | 《剧本 Learning 审核标准》；《剧本整体审核及评测标准》；《分级剧本要求》。 |
| **《示例短剧》例子** | 实习生输出《示例短剧》各等级正式英文版，并记录第二集 2-1 的语言问题和修改结果；人物、场景和身份反转在各版本中保持一致。 |

### 板块二｜知识点与题目输出

> **完成标准：**知识点必须真实出现在正式台词中并符合目标等级；题目分为片中互动题和文本练习题两类。

#### Step 6｜按各等级正式剧本匹配知识点

| **输入** | 各等级完善版正式剧本、对应等级知识库。 |
|-|-|
| **负责人** | 教研负责人及教研团队。 |
| **操作** | 从角色正式说出的台词中提取候选知识点，回查对应等级知识库；词形需标回原型，短语必须整条命中。 |
| **输出** | 按剧集、语言等级整理的候选知识点清单。 |
| **项目文档／规范** | 《剧本语言与知识点要求》；标黄知识点必须命中对应等级知识库。 |
| **《示例短剧》例子** | 第二集 2-1 可匹配 report a theft、verify your identity、under Italian law 等候选知识点。 |

#### Step 7｜确认单集和整部剧的知识点数量

| **输入** | 候选知识点清单、每集正式英文对白词数、对应等级知识库和全剧集数。 |
|-|-|
| **负责人** | 教研负责人及教研团队。 |
| **操作** | 先建立候选池，再选择最终核心知识点：候选池数量不少于“正式英文对白词数 ÷ 45”四舍五入后的数量；生产预选可按最终需求的约 200% 准备；最终核心知识点按约 90 个英文对白词对应 1 个、每集允许上下浮动 1 个，并且每集最多 3 个。50 集整剧 100–150 个是项目规划目标，不作为脱离台词量和知识库命中的硬性验收线。 |
| **输出** | 每集候选知识点池、最终核心知识点、台词位置、知识库 ID 和整剧覆盖表。 |
| **项目文档／规范** | 《剧本整体审核及评测标准》；《剧本 Learning 审核标准》；《内容生产流程会议总结》。 |
| **《示例短剧》例子** | 第二集 2-1 先从正式对白提取 report a theft、verify your identity、under Italian law 等候选，再按台词量和教学价值确定最终核心知识点；不为了凑满 2–3 个而使用不在知识库或不自然的表达。 |

#### Step 8｜按固定题型生成候选题

| **输入** | 已确认核心知识点、知识点 ID、语言等级、学习方式和正式题型规范。 |
|-|-|
| **负责人** | 出题 Agent 生成；教研负责人及教研团队管理生成任务。 |
| **操作** | 原则上围绕每个核心知识点准备 3 种不同题型，形成足够的候选题；先确定全英文学习或母语辅助学习，再从《各级别题型详细设计》中选择该等级已经确认的题型，生成题干、选项、唯一答案、反馈和所需素材。标有“待确认”的题型不能作为正式生产依据。 |
| **输出** | 片中互动题候选和文本练习题候选；每道题带知识点 ID、题型、等级、学习方式、答案、反馈和素材信息。 |
| **项目文档／规范** | 《各级别题型详细设计》；《出题生产与交互策略》；《内容生产流程会议总结》。 |
| **《示例短剧》例子** | 围绕 verify your identity，按 B2 已确认题型生成听音选择、语境填空、句子排序等不同候选题，并保留同一知识点 ID。 |

#### Step 9｜系统检查和教研审核题目

| **输入** | 片中互动题候选、文本练习题候选和关联知识点。 |
|-|-|
| **负责人** | 系统自动检查；教研负责人及教研／审校人员人工审核。 |
| **操作** | 检查信息完整、题型格式、答案唯一、知识点对应、等级难度、选项、题干、剧情语境和所需素材。未通过时编辑或返回重新生成。 |
| **输出** | 审核通过的片中互动题内容和文本练习题库。 |
| **项目文档／规范** | 《题目测评标准－教研侧》；《教研 CMS 产品需求文档》。 |
| **《示例短剧》例子** | 填空题“Without your passport, I cannot ____ your identity.”只能接受 verify，并提供清楚的答案解析。 |

### 板块三｜教学（剧情与题目）内容视频制作

#### Step 10｜制作剧情视频、出题视频和字幕

| **输入** | 各等级正式剧本、人物和角色设定、场景与视觉资产。 |
|-|-|
| **负责人** | 编导负责人及内容团队；视觉资产由设计负责人及设计团队提供。 |
| **操作** | 按正式剧本生产剧情视频、出题需要的互动视频和字幕；检查人物、角色、场景、台词和剧集顺序。 |
| **输出** | 待审核的剧情视频、互动视频、字幕和视觉资产。 |
| **项目文档／规范** | 《端到端流程图》。现有知识库规定了视频验收标准，但尚未完整规定分镜、配音、口型和剪辑的内部生产步骤。 |
| **《示例短剧》例子** | 制作 Sophia 在民宿说明被盗、Jacob 拒绝入住、Sophia 认出面具舞伴的剧情视频和对应英文字幕。 |

#### Step 11｜完成 AI 剧情视频八项质量审核

| **输入** | 剧情视频、互动视频、字幕和正式剧本。 |
|-|-|
| **负责人** | 内容团队人工审核；问题返回视频制作环节。 |
| **操作** | 审核剧本与叙事、导演与镜头、摄影与美术、表演与角色、声音、后期、AI 技术一致性和综合可用性。 |
| **输出** | 审核通过的视频、字幕和视觉资产。 |
| **项目文档／规范** | 《内容侧视频评测标准》。 |
| **《示例短剧》例子** | 检查 Sophia 与 Jacob 的人物外观是否连续、对话口型和声音是否同步、民宿场景是否一致、身份反转是否表达清楚。 |

#### Step 12｜制作片中互动题和配套互动视频

| **输入** | 审核通过的剧情视频、核心知识点、片中互动题候选和剧情理解题候选。 |
|-|-|
| **负责人** | 教研确定题目内容；内容团队确定可用剧情位置、制作配套互动视频并完成人工审核。 |
| **操作** | 选择知识点题或人物、事件、原因等剧情理解题，生产侧固定题目出现时间；制作进入题目、出题、等待、答对／答错讲解和返回剧情的完整互动片段。当前选择与分发按视频时长控制题目上限，实际被选中的题目时间间隔必须大于 45 秒；早期会议中的“最多 2 题、间隔 30 秒”仅保留为历史方案。 |
| **输出** | 每集片中互动题包，包含题目信息、配套互动视频、剧集 ID、固定时间点、顺序和审核状态。 |
| **项目文档／规范** | 《出题生产与交互策略》；《内容生产流程会议总结》。 |
| **《示例短剧》例子** | 在 Jacob 拒绝入住后的固定时间点出现：“为什么 Jacob 不能让 Sophia 入住？”答题后解释“因为她没有护照，Jacob 无法确认身份”；如果同集还有其他题，系统按当前间隔规则选择可用题目。 |

#### Step 13｜形成审核通过的文本练习题库

| **输入** | 审核通过的文本练习题、答案、解析及所需音频图片。 |
|-|-|
| **负责人** | 教研负责人及教研团队。 |
| **操作** | 整理题目与知识点、等级、题型和素材的关联；文本练习题不固定在视频时间点，可由不同学习场景选择组合。 |
| **输出** | 可用于每集结束后的练习、每 5 集复习和跳集测试的文本练习题库。 |
| **项目文档／规范** | 《出题生产与交互策略》；《各级别题型详细设计》。 |
| **《示例短剧》例子** | 围绕 verify your identity 准备词义选择、填空、排序和听音题；播放本集后可从题库中组合剧后练习。 |

#### Step 14｜联合编排并输出可入库教学内容包

| **输入** | 剧情视频、字幕、片中互动题包、知识点、文本练习题库和视觉资产。 |
|-|-|
| **负责人** | 编导负责人负责视频与剧集内容；教研负责人负责知识点和题目；出题与组装负责人、出题与组装协作人确认使用规则。 |
| **操作** | 将片中互动题按时间放入剧情视频；文本练习题库作为独立题库资产，不放入视频时间轴；检查各资产版本一致。 |
| **输出** | 可进入课程编排和入库的教学内容包。 |
| **项目文档／规范** | 《课程生成过程讨论》；本页端到端流程图。 |
| **《示例短剧》例子** | 内容包包含第二集 2-1 正片、英文字幕、片中题出现时间、对应互动视频、知识点和可供剧后练习选择的文本题。 |

### 板块四｜课程编排、入库与发布

#### Step 15｜整理并上传所有原子内容

| **输入** | 经过人工确认、最终会被用户看到或使用的正式剧本、视频、字幕、知识点、两类题目、人物、角色、封面和图片，以及稳定 ID 对照表。 |
|-|-|
| **负责人** | 编导负责人上传剧集内容；教研负责人上传知识点和题目；设计负责人及设计团队上传视觉资产；CMS 总负责人负责 CMS 总体协调。 |
| **操作** | 只把最终可供用户消费的内容放入核心 CMS，过程稿和中间文件可留在生产工具中。按稳定 ID、统一命名、语言等级和版本建立内容对应表；通过上传接口获取短时有效的上传地址，上传后由系统检查元数据和媒体，并完成所需转码。所有内容先进入草稿／待审核状态。 |
| **输出** | 可供编排的正式内容草稿、系统检查结果、媒体处理结果和完整内容对应表。 |
| **项目文档／规范** | 《内容体系与入库协作说明》；《教研 CMS 产品需求文档》；《内容生产流程会议总结》。 |
| **《示例短剧》例子** | 上传第二集 2-1 的正式英文剧本、正片、字幕、片中互动题包、文本题、Sophia／Jacob 角色和民宿场景资产；专家审校过程稿不作为 App 消费内容进入核心库。 |

#### Step 16｜创建剧集并组成短剧

| **输入** | 已上传的原子内容和正确的剧集顺序。 |
|-|-|
| **负责人** | 编导负责人负责剧集内容和顺序；教研负责人负责知识点与片中题关联。 |
| **操作** | 先创建单集内容，关联正片、字幕、知识点和片中题时间点；再按顺序把多个剧集组成短剧，配置语言等级、封面、人物和角色。 |

| **《示例短剧》例子** | 创建“第二集 2-1 威尼斯民宿”剧集，绑定正片、字幕、verify your identity 和片中题；再按集数加入《示例短剧》B2 英文版短剧。 |

#### Step 17｜组装课程、自动检查并完成人工上线审核

| **输入** | 短剧草稿、文本练习题库、学习主线、语言等级、稳定 ID 对应表和分发规则。 |
|-|-|
| **负责人** | 出题与组装负责人、出题与组装协作人负责最终组装；系统自动检查；编导负责人完成剧集内容维度签字，教研负责人完成知识点与题目维度签字，出题与组装负责人完成整体确认。 |
| **操作** | 按依赖顺序组装课程并检查关联关系：学习主线和等级有效；短剧至少有 1 集且集序连续不重复；每集正片和字幕有效；每集至少有 1 个合法知识点；每集至少有 1 道已发布、时间合法且顺序递增的片中互动题；每个知识点至少有 1 道已发布的文本练习题；所有媒体可用、等级和知识点关系合法。任何一项失败都退回对应负责人修改并重新检查。 |
| **输出** | 系统检查通过，且剧集内容、知识点与题目、整体课程三方人工确认完成的待发布课程。 |
| **项目文档／规范** | 《内容体系与入库协作说明》；《教研 CMS 产品需求文档》；《内容生产流程会议总结》。 |
| **《示例短剧》例子** | 组装英语 B2《示例短剧》课程；若 Sophia 角色错误、字幕与视频不匹配、片中题时间超出视频、verify your identity 没有文本练习题或答案错误，必须退回修改，不能进入发布。 |
